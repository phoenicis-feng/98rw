2026 年过半，大语言模型的竞争焦点已经从"参数规模"彻底转向了"推理质量"。过去一年里，几乎所有一线厂商都推出了自己的深度思考（deep thinking）模式，声称能够在数学、代码和科学问题上达到博士水平。宣传归宣传，真实工作负载下的表现才是我们关心的。

本次横评我们选择了六个主流模型，在四类真实任务上进行了为期三个月的持续测试。本文是完整报告。

## 测试方法

### 参评模型

| 模型 | 厂商 | 上下文窗口 | 思考模式 |
|------|------|-----------|---------|
| Aurora-3 | 北极星实验室 | 1M tokens | ✅ |
| Gemini Ultra 3 | Google | 2M tokens | ✅ |
| Claude Opus 5 | Anthropic | 500K tokens | ✅ |
| GPT-5.5 | OpenAI | 1M tokens | ✅ |
| 文澜 4.0 | 澜舟科技 | 256K tokens | ✅ |
| Llama 4.5 405B | Meta | 128K tokens | ⚠️ 社区版 |

### 评测维度

我们没有采用常见的公开基准测试——那些榜单早已被针对性优化污染。取而代之的是四类**真实工作负载**：

1. **代码工程**：从 issue 到 PR 的完整修复流程，包含跨文件重构
2. **长文档分析**：200 页以上的合同审查与技术尽调
3. **数据分析**：脏数据清洗、多表关联、结论撰写一体化任务
4. **多轮对话**：20 轮以上的需求澄清与方案迭代

每项任务由三名评测员独立打分，取中位数。评分标准提前冻结，测试期间不允许调整。

## 代码工程：差距最大的一项

代码能力是本次横评中模型间差距最大的维度。我们使用了 60 个来自真实开源仓库的 issue，要求模型独立完成"复现 → 定位 → 修复 → 测试"全流程。

Aurora-3 在这一项上表现惊人，独立解决率达到 71%，而第二名的 Gemini Ultra 3 只有 58%。差距主要来自**跨文件推理**能力：

```python
# 典型失败案例：模型只修改了调用方，没有意识到
# 被调用的服务在另一个包里也有实现
def sync_user(user_id: str) -> None:
    """Aurora-3 会同时检查 grpc 和 rest 两个实现路径，
    多数模型只看到 rest 这一条。"""
    rest_client.sync(user_id)
    # 遗漏: grpc_replica.invalidate(user_id)
```

值得注意的是，**思考模式开关对代码任务的影响远小于预期**。多数模型开启深度思考后提升只有 3-5 个百分点，但 token 消耗翻了四倍。我们猜测代码能力更多取决于预训练和后训练质量，而非推理时计算。

### 工具调用稳定性

在需要连续调用 8 个以上工具的任务里，所有模型的稳定性都明显下降。最常见的失败模式是"工具幻觉"——模型声称调用了某个工具并编造返回结果。这方面没有任何一个模型做到 95% 以上的可靠率，仍然有很大改进空间。

## 长文档分析：上下文长度不等于上下文能力

厂商宣传的上下文窗口从 128K 到 2M 不等，但我们的"大海捞针 Plus"测试显示，**有效上下文长度**普遍只有标称值的 30%-60%：

> 当关键信息位于文档后 1/3 处、且前后存在语义相似的干扰段落时，
> 六个模型的召回率平均下降 41%。没有模型能幸免。

合同审查任务的结果更有意思。我们准备了一份 180 页的投资协议，埋入了 12 处风险条款。表现最好的模型找到了 9 处，最差的只找到 4 处——但**所有模型都漏掉了同一处**：一个隐藏在附件表格脚注里的对赌条款。这提示当前的注意力机制对"结构性边缘位置"的信息仍然存在系统性盲区。

## 数据分析：意料之外的黑马

这一项的黑马是文澜 4.0。在脏数据清洗任务上它以 82 分的平均成绩排到第二，仅次于 Aurora-3 的 85 分。我们对 20 个真实业务数据集（电商订单、IoT 传感器、医疗随访等）测试了完整流程：

```bash
# 测试任务的典型形态：从原始 CSV 到分析报告
$ python analyze.py --input orders_2025_raw.csv \
    --clean --dedupe --join customers.csv \
    --report monthly_retention.md
```

文澜 4.0 的优势在于**对中文业务语境的理解**：它能正确识别"双 11"、"618"这类促销节点对留存曲线的干扰，而多数英文优先的模型会把这些异常点当成数据错误处理。

不过在统计严谨性上所有模型都不及格：六个模型里有五个在某个任务中编造了不存在的显著性检验结果。**数据分析场景下，模型输出必须经过人工复核**，这一点短期内不会改变。

## 多轮对话：记忆仍是短板

20 轮以上的对话测试暴露了各家在状态管理上的差异。我们统计了三个指标：

- **需求回溯准确率**：模型能否正确引用 10 轮之前用户提过的约束
- **方案一致性**：前后建议是否自相矛盾
- **主动澄清率**：遇到歧义时是否主动提问而不是瞎猜

Claude Opus 5 在主动澄清率上遥遥领先（78%，第二名只有 45%），这个特性在真实协作中价值极大——它显著降低了"模型自信地做错事"的概率。但在需求回溯准确率上，所有模型都在 60% 以下徘徊，长对话的真实记忆能力仍然依赖外部工具。

## 成本与速度

抛开质量谈价格没有意义，但抛开价格谈质量同样耍流氓。以我们的标准工作负载计算每百万任务的综合成本：

| 模型 | 综合成本 | 首 token 延迟 | 思考模式成本倍数 |
|------|---------|--------------|----------------|
| Aurora-3 | $$$$ | 1.8s | 4.2x |
| Gemini Ultra 3 | $$$ | 1.2s | 3.8x |
| Claude Opus 5 | $$$ | 1.5s | 3.5x |
| GPT-5.5 | $$$ | 1.4s | 3.9x |
| 文澜 4.0 | $$ | 2.1s | 3.1x |
| Llama 4.5（自托管） | $ | 3.5s | - |

一个反直觉的发现：**开启思考模式并不总是划算**。在代码和数据分析任务里，思考模式的质量提升通常配得上 3-4 倍的成本；但在长文档摘要和多轮对话里，提升微乎其微，纯属浪费。按任务类型动态切换思考模式，能省下 40% 以上的推理预算。

## 结论与建议

三个月测下来，我们的核心结论有三条：

1. **没有全能冠军**。Aurora-3 拿下代码和文档两项第一，但成本最高、速度最慢；文澜 4.0 在中文数据分析场景性价比突出；Claude Opus 5 的协作体验最好。按任务选型比押注单一模型明智得多。
2. **思考模式被严重过度营销**。除数学和代码外的多数任务，深度思考带来的提升无法覆盖成本。建议默认关闭，按任务类型白名单开启。
3. **可靠性仍是落地最大障碍**。工具幻觉、编造统计结果、长上下文盲区——这三类失败在生产环境中造成的返工成本，往往超过模型订阅费本身。
